# 要求：
1. 技术栈采用 Python 开发，使用 NV 作为环境管理

# 背景：
在一期视频的创作中，AI 语音生成涉及多个平台。例如 IndexTTS、GPT-SoVITS 等。这些引擎通常使以 webui 的形式提供。导致文案完成后，需要人工按将其一句一句输入不同的平台，微调后还需要经过下载->重命名->整理等操作，并且通常每句话需要多次生成确定效果，整体流程非常繁琐。因此需要一个软件进行优化。
# 需求：
1. 引入任务集的概念。一个任务集对应一个目录，目录里对应着所有任务的配置，包括文案，生成引擎，以及根据不同生成框架有不同的入参，最终输出的音频文件。
2. 引入任务的概念，一个任务对应着一句语音生成，包括文案，生成引擎，以及根据不同生成框架有不同的入参。
3. 整体分为两个 tab 页面，第一个是软件配置，包括配置不同引擎的 url，与任务集。第二个是任务列表，含有以下元素：任务列表，任务详情，任务列表有选中状态，选中后任务详情会展示选中任务的配置，以及任务的状态，包括未开始，队列中，生成中，生成完成，生成失败。任务列表支持排序，支持批量操作，包括批量生成，批量删除，批量下载。任务详情支持编辑任务，支持删除任务，支持下载任务。
4. 内部维护一个任务队列，点击批量生成后将选中的任务添加到队列，这些任务变成队列中状态。队首会调用引擎 API 进行生成，生成完成后会将任务状态改为生成完成，生成失败后会将任务状态改为生成失败。
5. app顶部维护一个全局播放器，生成后的任务可以点击播放，支持参考音频的特定引擎在任务详情选择参考音频后也可以点击播放参考音频。播放器全局维护一个实例，支持暂停操作，新的播放会停止旧的播放。
6. 所有任务的配置状态都要持久化，保存在任务集路径中。如果为生成完成状态，同时还要保存一个当前音频文件对应的生成配置。
7. 音频文件名以任务id和文案标准化（去除特殊字符）命名。
8. 初步打算支持的引擎为 IndexTTS 和 GPT-SoVITS。每个引擎有自己的入参格式和配置块。当任务详情面板选中对应引擎时，会展示对应引擎的配置块。
9. 引擎的 webui 已开启，拥有对应的 url，需求文档中先占位。同时需要对接环节，根据 url，调用对应工具判断 api，并实现对应功能。
# 备注:

* 上传情感参考音频

    * Calm
    * Surprised
    * Melancholic
    * Disgusted
    * Afraid
